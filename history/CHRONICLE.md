# Chronicle

The project's rounds, in order, as `PROJECT.md`'s `status` and `notes` fields
recorded them.

**Why this file exists.** The resume card is read at the start of every session so
that a session can resume *instead of* reading the repository. By 2026-10-03 its
`status` field had grown to 20,000 characters and `notes` to 9,060 — together
longer than `transform.rb`, `builder.rb` and `generator.rb` combined, and held in a
single folded YAML scalar with no paragraph breaks, which cannot be skimmed,
linked or navigated. The instrument built to save a session from reading the repo
had become longer than the part of the repo it describes. `DAYTRIP-0.4.0h.md`
called that "the same disease in the instrument built to stop it".

**Nothing here was rewritten and nothing was deleted.** That matters, because the
assumption going in — stated in the audit's Tier 7 and again in `HANDOFF.md` — was
that this text duplicated the `DAYTRIP-*.md` files and could simply go. It does
not: twenty-four phrases sampled from the two fields were found **nowhere else in
the repository**. It is independently written prose about the same events, and the
only connected, compressed account of them in order. So it moved rather than went,
and `PROJECT.md` now says where the project stands and points here.

It sits in `history/` because that is where this project keeps what is consulted
rather than read. It is not maintained: a round's record is its `DAYTRIP-*.md`
file, and the card carries only the present.

The headings below are the five round boundaries identifiable from the text with
confidence. Within the first, paragraph breaks fall at the narrative's own "Then …"
transitions; no round attribution was invented for them.

## 2026-10-03 — Daytrip 0.4.0l: the most-travelled datum gets a name

Daytrip 0.4.0l (2026-10-03) ran Tier 6 item 18: the semantic node, a bare three-element Array for the project's first month, is now `SlimPickins::Node = Data.define(:word, :attributes, :children)`.
